# 공식 일정 화면·운영 경계

## 구현 범위

- `/schedules`: URL의 `month=YYYY-MM`으로 한국 시간 월을 이동합니다. 월간 보기와 목록, '내 가수만' 필터를 제공합니다. 끝나는 시각이 있는 일정은 월/날짜 구간이 겹치면 표시하고 종료 시각 그 자체는 다음 날/다음 달에 포함하지 않습니다.
- 내 가수는 **현재 구독 이용 권한이 있는 active 가수**입니다. 기존 접근 함수가 허용하는 유예 기간과 해지 후 남은 이용 기간을 포함합니다. 가입 시 관심 가수 선택은 구독으로 취급하지 않습니다.
- 첫100개와 정밀 시작 시각/UUID 커서로 더 불러오기를 제공합니다. 아직 불러오지 않은 일정이 있음을 명시하며, 필터 결과가 현재 페이지에 없어도 더 불러오기를 숨기지 않습니다. 달력은 불러온 일정만 표시합니다.
- `/schedules/[id]`: 현재 공개 상태인 active 가수 일정만 조회합니다. 로그인/현재 제한 상태와 팬 온보딩 준비를 확인합니다. 제목·설명·장소는 텍스트로 렌더링하며 임의 HTML이나 저장된 URL을 실행하지 않습니다.
- `/admin/schedules`: 현재 관리자만 월별 초안/공개 목록, 등록·수정·삭제를 사용합니다. 비활성 가수 일정은 관리할 수 있지만 팬에게 공개되지 않는다고 표시합니다. 일정의 가수는 생성 후 변경하지 않습니다.
- 기존 데이터 모델의 초안/공개와 감사 기록을 유지합니다. 일정별 알림 설정/전날 알림과 콘텐츠 캘린더 UI는 다음 기능이며 이번 기능에서 활성화하지 않습니다.

## 날짜·시간의 기술적 경계

한국 시간은 고정 `UTC+09` 계산이 아니라 `Asia/Seoul` 시간대 규칙으로 해석합니다. 과거 표준시/DST 변경을 포함하여 달력 월/날짜 경계는 PostgreSQL과 동일한 기준으로 검증합니다. 사용자가 선택한 현지 시각이 DST 전환 때문에 존재하지 않으면 입력 오류로 거절하고 자동으로 다른 시각으로 이동하지 않습니다. 반복되는 시각은 PostgreSQL과 같이 더 늦은 실제 시각을 선택합니다.

새 관리 API는 UTC로 직렬화 가능한 네 자리 ISO 연도(0001 이상), 초 단위와 최대6자리 소수초만 허용합니다. PostgreSQL의 마이크로초 정밀도를 유지하며 표현 범위를 넘는 소수초를 조용히 반올림하지 않습니다. 기원전/UTC 연도0000으로 바뀌는 극초기 현지 날짜는 기술적 표현 범위 밖이며, 특정 운영/사업상 시작 연도를 승인한 것이 아닙니다. 기존 레거시 DB의 광범위 날짜 계약은 변경하지 않습니다.

## 수정·재시도

실제 변경은 actor-bound RPC 하나의 트랜잭션으로 처리합니다. 관리자의 현재 역할/제한을 잠금 뒤 다시 확인하고, 현재 revision과 폼의 예상 revision이 다르면 덮어쓰거나 삭제하지 않습니다. 공개 및 삭제는 명시적 확인 절차가 있습니다.

작업 UUID와 정확한 제출 본문을 동일하게 재전송하면 기존 승인 결과를 재사용합니다. 같은 UUID에 다른 본문을 넣거나 오래된 revision을 보내면 충돌입니다. 응답이 유실되어 성공 여부를 모르면 성공이라고 표시하지 않고 같은 요청을 확인하도록 안내합니다. 기존 승인된 레거시 CRUD RPC는 호환성을 유지하되 revision을 증가시키므로 새 폼의 충돌 검사를 무력화하지 않습니다.

개인 구독 필터/관리 초안은 재사용 가능한 RSC 데이터에 넣지 않습니다. 브라우저 API 응답은 private/no-store이며 현재 권한을 매 요청 확인하고, 오래된 응답·탭 복원·이동과 권한 변경을 고려합니다. 새 페이지의 식별자나 month/page와 맞지 않는 응답을 받아들이지 않습니다. 페이지가 처음 확인한 actor 식별자를 같은 출처 요청에 바인딩하고 새 인증 주체와 다르면 거절합니다. 이 바인딩은 권한을 부여하지 않으며, 계정이 바뀐 뒤 이전 계정의 불명 작업을 새 작업으로 재전송하지 않게 합니다.

## 지도 링크와 개인정보

지도 SDK, 지오코딩, 브라우저 위치 권한, 자동 이동, 자동 앱스토어 분기, 서버 지도 요청을 사용하지 않습니다. 사용자가 링크를 직접 누를 때만 외부 지도/앱으로 이동합니다. 외부 링크는 `noopener noreferrer`와 `referrerPolicy=no-referrer`를 사용합니다.

- Kakao: 공식 문서의 `https://map.kakao.com/link/map/{lat},{lng}`. 공개 행사 좌표만 포함합니다. [Kakao 지도 바로가기 계약](https://apis.map.kakao.com/web/guide/#mapurl)
- Naver: 공식 `nmap://map?lat=...&lng=...&appname=...` 앱 링크. `appname`에는 설정된 **공개 앱 origin만** 넣고 현재 경로·쿼리·사용자 정보는 넣지 않습니다. 설치된 앱이 필요함을 표시하고 Kakao 웹 링크도 제공합니다. 문서의 지원 좌표 범위(위도31.43–44.35, 경도122.37–132.00) 밖에서는 Naver 버튼을 숨깁니다. 좌표 자체를 변경/반올림하지 않습니다. [Naver URL Scheme 계약](https://guide.ncloud-docs.com/docs/maps-url-scheme)
- 개인 식별자·내 위치·세션·호출 이름·구독 여부·비공개 설명을 지도 서비스에 전송하지 않습니다. 외부 지도 앱의 실제 설치/열림은 CI에서 검증한 사실이 아닙니다.

키를 요구하지 않는 공식 링크 계약이므로 지도 API 키를 추가하거나 가짜 어댑터 성공을 만들지 않습니다. 기존 Auth/Supabase 설정이 없으면 준비 중 상태를 표시합니다.

## 검증

- `npm run check:all`: 형식·린트·타입·단위·대비·빌드.
- `npm run test:schedules-fixture`: 격리 CI 설정/가드 계약. 외부 서비스 접속 없음.
- `npm run test:integration`: 실제 로컬 PostgreSQL의 권한, 범위, CAS, 재시도, 감사 기록 검증. CI에서 두 번 실행합니다.
- `npm run test:db:schedule-management-concurrency`: 별도 PostgreSQL 세션14개 경쟁 시나리오. 로컬 기본 Unix-socket Docker만 허용하고 허구 테스트 DB를 복구합니다.
- `node scripts/test-schedule-management-upgrade.mjs`: version29 데이터가 있는 상태에서 마이그레이션 후 원본·공개 뷰·기존 알림 선호·콘텐츠·감사·프로필 보존 확인.
- `npm run test:e2e:schedules`: 전용 격리 CI job에서 실제 로컬 Auth/RPC/DB와 허구 일정을 사용합니다. 글자3단계×360/1280의 실제 정착 URL/제목, 전체 화면 및 화면 아래 지도/등록/삭제 조작 요소를 별도 캡처합니다. 지도 URL은 검사만 하고 공급자로 이동하지 않습니다.

DB 타입은 실제 CI의 공식 CLI 생성 artifact를 바이트 그대로 반영합니다. 편집 환경의 Docker/브라우저 제한은 통과로 기재하지 않으며 실제 CI·픽셀 검수와 구분합니다. 실제 운영 계정·메시지·결제·개인 위치·정책 승인·배포·Cron 실행은 없습니다.
