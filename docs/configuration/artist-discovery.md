# 가수 탐색·개인화 맛보기·관심 선택

## 이번 기능에서 제공하는 것

- `/start`의 공개 목록 진입과 `/artists`의 active 가수 목록. `artist_catalog`에서 `slug,name,intro`만 명시적으로 읽고 안정적인 slug 순서로 12개씩 페이지를 나눈다. 계약·등급·소속·내부 가수 ID·원본 사진 경로는 브라우저 DTO에 없다.
- `/artists/[slug]`는 **맛보기 전용**이다. 현재 팬 세션, 제한 상태, 저장한 글자 크기·이름·나이 자기 확인·현재 승인된 필수 동의를 확인한다. 완전한 온보딩 전이어도 이 프로필 단계를 마쳤다면 맛보기를 볼 수 있다. 이미 결제한 사용자를 위한 대화방은 후속 기능이며 이 화면이 유료 접근권을 대체하지 않는다.
- `src/server/services/message/render.ts` 한 곳에서 DB가 현재 정책으로 검증한 `call_name`만 `{이름}`에 치환한다. 결과는 **일반 텍스트**로 React에 전달한다. HTML 해석, 클라이언트 치환, 정규식 치환 문자열의 `$&` 해석은 하지 않는다. 원문·별도 이름 필드·작성자·구독·소속 ID는 결과에 포함하지 않는다.
- `/onboarding/artists`는 **관심 가수 한 명의 선호**만 저장한다. 결제·구독 생성/전이·유료 열람·읽음 증거를 만들지 않는다. 선택 확인 모달에도 이 차이를 알린다. 선택 없이 건너뛰는 정책은 승인 근거가 없어 제공하지 않는다.
- 성공한 선택은 `/onboarding/install`로 이어진다. 현재 화면은 관심 저장 결과와 **설치 안내 준비 중**을 명확히 보여 주며 설치/PWA/알림 권한을 구현했다고 주장하지 않는다. `onboarding_completed_at`은 변경하지 않는다.

## 데이터와 보안 경계

[DB 계약](../database/artist-discovery.md)의 migration 00011이 선행되어야 한다. 관심은 `auth.uid()` RPC만 사용하고, 요청 본문은 `{slug}`만 허용한다. 타인 ID·role·이름·완료 플래그를 추가하면 거절한다. API는 검증한 Origin, 크기 제한 UTF-8 JSON, 현재 세션/팬/제한/미완료 상태를 확인한다. DB가 현재 정책과 active 가수를 다시 확인하며 동시 상태 변경을 잠금으로 직렬화한다.

원문 맛보기는 authenticated/anon RPC로 공개하지 않는다. 서버 전용 `discovery_preview` RPC에 **검증된 세션의 subject**만 전달하고 서버 개인화 뒤 허용 필드만 반환한다. 이를 위해 기존 환경 변수 `SUPABASE_SERVICE_ROLE_KEY`가 필요하다. 인증·목록·관심 저장은 여전히 공개 키의 요청별 actor client를 사용한다. 서비스 키를 `NEXT_PUBLIC_*`, client props, 응답, 로그, 쿠키, 브라우저 SDK에 전달하지 않는다. 서버 client는 세션 유지/자동 갱신을 끄고 `no-store` 및 요청 timeout을 적용한다.

키/정책 미준비는 준비 중 오류이고, 존재하지 않는/초안/중지/은퇴한 가수는 동일한 이용 불가 상태다. 제한·다른 역할은 거절한다. 이전 필수 동의가 현재 버전과 다르면 재동의 전 맛보기/선택이 막힌다. full-completed 기존 계정의 새 정책 재동의 설정 화면은 아직 별도 기능이므로, 해당 경우에도 접근을 허용하는 대신 차단한다.

미디어 메시지의 텍스트는 개인화되지만 미디어는 종류가 지정된 `availability: unavailable` placeholder다. **사진/음성/영상 다운로드·재생·서명 URL은 미구현**이며 브라우저에 bucket/path/object ID/원본 URL을 주지 않는다. 프로필 사진도 외부 URL 또는 임의 origin에서 가져오지 않는다. 미디어 접근 및 서명 기능은 별도 권한 검증과 함께 구현해야 한다. 실제 아티스트·라이선스 콘텐츠·운영 정책을 seed하지 않는다.

## 중단·재시도·접근성

선택 성공은 DB 커밋 응답 뒤에만 표시한다. 같은 가수를 다시 선택하면 최초 선택 시각을 보존한다. 응답 유실은 실패 확정이 아닌 결과 불확실로 안내하고 같은 선택을 안전하게 재시도한다. 모달 취소/닫기/이전 이동은 저장하지 않으며 중복 클릭을 막는다. 화면을 떠난 후 늦은 응답으로 새 화면을 되돌리지 않는다.

다시 로그인한 `/onboarding`은 저장된 active 관심이 있으면 설치 대기 단계로, 없거나 가수가 비활성화되었으면 선택 단계로 이어진다. 선택 화면으로 돌아가 바꿀 수 있다. 비활성화된 관심의 숨겨진 가수 정보는 보여 주지 않는다. 정책이 바뀌면 이전 필수 프로필 단계부터 다시 확인한다.

공통 Button/BackButton/Card/InlineError/Loading 및 Radix 모달을 사용한다. 한국어 next-intl 문구, 최소 48px 조작 영역과 normal/large/xlarge 글자 크기를 유지한다. 빈 목록·빈 맛보기·불러오는 중·인라인 오류·재시도·페이지 이동을 제공한다.

## 검증과 남은 경계

- 실제 DB/권한/경합 검증은 공식 Supabase PostgreSQL CI에서 수행한다. 로컬 PGlite는 보조 SQL 증거일 뿐이다. 타입은 migration checkpoint CI의 실제 생성 artifact만 반영한다.
- 별도 auth-browser CI는 폐기용 local Auth와 허구 가수/텍스트/Storage metadata만 사용한다. Kakao·외부 제공자·실사용자·실제 이미지 URL을 호출하지 않는다. 서비스 키 유출 여부는 값을 출력하지 않는 boolean 검증으로 확인한다.
- 로컬 브라우저 실행은 권한 제한으로 실행하지 않는다. 3개 글자 크기 × 360/414px 화면·모달·설치 대기의 CI 스크린샷을 별도로 검토한다. 통과 여부는 work-log와 exact-head CI 결과로 구분한다.
- 실제 운영 계약/정책 활성화, Kakao 원격 로그인, 서명 미디어, 유료 대화/결제, PWA 설치/알림, `preview_view` 분석 전송, staging/production 배포는 이 기능의 완료 주장에 포함하지 않는다. 분석 동의나 preview 조회 성공을 임의 이벤트 증거로 만들지 않는다.
