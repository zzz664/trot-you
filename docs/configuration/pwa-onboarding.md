# PWA 설치 안내와 전체 온보딩 완료

## 사용자에게 약속하는 범위

`/onboarding/install`은 현재 유효한 프로필과 활성 관심 가수를 확인한 뒤, 실제 브라우저에서 사용할 수 있는 설치 방법을 안내한다. iOS/iPadOS는 공유 메뉴 → 홈 화면 추가, Android는 실제 `beforeinstallprompt` 이벤트를 받은 경우에만 설치 버튼, 그 밖의 브라우저는 메뉴 안내와 지원 제한을 보여 준다. 홈 화면 실행 여부와 설치 이벤트는 관측일 뿐 서버의 검증된 설치 증거로 바꾸지 않는다.

사용자는 **안내 확인 / 지금 설치하지 않음 / 직접 설치했다고 알림** 중 하나를 명시적으로 저장한 뒤 별도 완료 버튼을 누른다. 설치가 불가능하거나 원하지 않는 기기에서도 안내를 확인하고 계속할 수 있다. 원본의 필수 설치 단계는 기술적으로 검증할 수 없는 설치 강제가 아니라 필수 **안내·선택 기록**으로 구현했다. 자기 보고는 별도 시각으로 보존하고 검증된 설치라고 표시하지 않는다.

알림 권한은 선택 사항이다. 홈 화면 실행·보안 컨텍스트·지원 API를 확인하고 **사용자가 알림 권한 버튼을 누를 때만** 브라우저 요청을 호출한다. 최초 렌더·로그인·가입 완료·서비스 워커 등록은 권한 요청을 일으키지 않는다. 거부·닫기·미지원에서도 가입을 마칠 수 있다. `granted`는 브라우저 권한일 뿐이며 **Web Push 구독 등록, 수신 가능 상태, 실제 알림 전달**을 뜻하지 않는다. 구독 API/VAPID/push 이벤트/알림 발송은 이 기능에 없다.

## 서버 권한과 재개

`POST /api/onboarding/install`은 정확한 설정 Origin, 실제 검증 세션, 현재 팬 역할과 제한 상태, JSON 본문 크기·strict schema를 확인한다. 사용자 ID, 역할, 완료 시각, 설치·알림의 검증 상태를 클라이언트가 지정할 수 없다. 현재 프로필/이름/정책 동의와 활성 관심 가수 및 저장된 안내는 actor-scoped DB 트랜잭션이 다시 확인한다.

안내 저장과 가입 완료는 각각 멱등 요청이다. 네트워크 실패는 결과 미확인으로 안내하고 같은 요청을 다시 보낼 수 있다. 완료 재요청은 최초 시각을 유지하지만 최신 정책·관심 조건을 다시 검사한다. 저장 후 새로고침·Back/Forward·재로그인으로 기록을 이어 간다. 이름/정책이 무효화되면 온보딩 입구에서 필수 단계를 복구하며, 가수가 비활성화되면 가수 선택으로 돌아간다. 완료된 계정은 설치 화면에 재진입하지 않고 홈으로 이동한다.

홈은 가입 준비 완료와 기록된 안내 선택만 보여 준다. 유료 구독·결제·대화방 접근·알림 활성화를 생성하거나 성공으로 표시하지 않는다. 과거 계정처럼 안내 기록을 확인할 수 없으면 확인 불가라고 표시한다. 선택적 분석 동의가 없어도 완료할 수 있으며 `signup_complete` 이벤트 수집은 후속 분석 연동 범위다.

## 정적 자산 전용 서비스 워커

Next.js 16의 기본 Turbopack 빌드 이후 Serwist configurator/CLI로 워커를 생성한다. 캐시 후보는 현재 빌드의 공개 JavaScript/CSS와 개인 정보 없는 명시적 `/offline.html`뿐이다. 미리 렌더한 앱 경로, 인증 HTML, RSC, API, OAuth, 미디어, 외부 요청, query·민감 요청 헤더는 캐시하지 않는다. 온라인 문서 요청은 네트워크에서 받고 네트워크 실패 때만 정적 오프라인 안내를 제공한다. 오프라인 안내는 기존 계정 정보나 과거 메시지를 보여 주지 않는다.

워커/manifest/icon/offline 파일은 세션 refresh proxy에서 제외한다. 워커 등록은 production build에만 있고 새 워커의 활성화와 오래된 전용 캐시·빌드 항목 정리를 검사한다. 로그인/로그아웃을 포함한 사용자의 인증 응답은 항상 서버 경계를 통과한다. 로컬·CI 캐시 검증을 실제 사용자 기기 설치 또는 iOS Web Push 검증으로 해석하지 않는다.

## 검증과 운영 한계

실제 Supabase/PostgreSQL의 pgTAP·독립 세션 경합·생성 타입 drift와 localhost Chromium의 인증 E2E·캐시/오프라인 검사는 CI에서 수행한다. 단위 테스트는 브라우저 기능 지원·허용/거부/닫기·중복 클릭·불확실한 응답·서비스 권한 경계를 다룬다. 3단계 글자 크기 × 360/414px 화면을 확인한다. 실제 iPhone/iPad 홈 화면 설치, Android 설치 UX, 실제 알림 권한 승인·Web Push 수신은 실행하지 않았고 별도 기기 검증이 필요하다.

운영 정책·가수 계약/콘텐츠·Kakao 설정 활성화·production 배포는 별도 승인 대상이다. 실제 키를 새로 발급하거나 알림을 보내지 않는다. 현재 실행 증거와 미실행 항목은 작업 로그 및 exact-head CI 결과를 기준으로 한다.
