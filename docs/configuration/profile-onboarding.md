# 프로필 온보딩 화면과 운영 준비

## 제공 범위

`/onboarding`은 저장된 단계로 이어 가는 입구다. `/onboarding/font` → `/onboarding/name` → `/onboarding/consent`에서 설정을 실제 서버 RPC로 저장한다. 마지막에는 `/onboarding/artists`의 [관심 가수 선택](artist-discovery.md)으로 이동한다. 관심 저장은 유료 구독이 아니며 전체 가입 완료도 아니다. [설치/알림 권한 안내와 전체 완료](pwa-onboarding.md)는 다음 단계이며 음성 입력과 실제 Web Push 전달은 이후 별도 기능이다.

- 글자 크기 세 단계는 선택 즉시 미리보기이며 **저장하고 다음** 성공 후 프로필과 HttpOnly 선호 쿠키에 저장한다. 로그인한 전체 문서의 첫 서버 렌더는 본인 프로필을 우선하고 로그인 전/조회 실패는 검증된 쿠키 또는 기본 large를 사용한다. Next의 재사용 layout에는 재진입 시 저장된 크기를 동기화한다.
- 이름은 단순 문자열이 아니라 DB에서 NFC 정규화, 앞뒤 공백 정리, 승인된 2–10 코드 포인트 범위와 금칙어를 검사한다. UI 검사는 권한 경계가 아니다.
- 만 14세 이상 확인은 사용자가 직접 선택하는 자기 진술이다. 생년월일·신분증을 받거나 외부 연령 인증을 완료했다고 주장하지 않는다.
- 약관/개인정보 문서의 실제 승인·공개 본문과 UUID 버전을 표시하고 각 항목을 별도로 선택받는다. 문서가 없으면 저장 버튼을 비활성화하고 준비 중 안내와 큰 재시도를 제공한다. 새 버전은 새 명시적 선택이 필요하다.
- 분석 동의는 기본 해제된 별도 선택이다. 해당 공개 문서와 기존 분석 구성 버전이 일치하는 경우에만 제공하며, 선택하지 않아도 필수 프로필 설정은 가능하다. 재제출 시 선택하지 않으면 기존 분석 동의도 철회된다. 이 화면에서 분석 이벤트 수집은 시작하지 않는다.

## 요청·접근 경계

`POST /api/onboarding`은 JSON만 받고 2 KiB의 기술적 요청 한도를 적용한다. 설정된 정확한 Origin, 검증된 현재 Auth subject, 현재 제한/전체 완료 상태를 확인한다. 서비스는 엄격한 단계별 입력을 검증하고 actor-scoped DB RPC만 호출한다. user ID, role, 완료 시각 등 추가 필드를 받지 않는다. 에러는 고정된 코드만 전달하고 입력/SQL/프로필 ID를 로그나 클라이언트 오류에 내보내지 않는다.

모든 하위 페이지에서 인증 상태와 저장된 선행 단계를 재검증한다. 미저장 단계 건너뛰기는 해당 선행 화면으로 이동한다. Back은 알려진 이전 화면이고, 첫 글자 화면 Back은 온보딩 입구다. 나중에 하기 버튼은 실제 로그아웃이며 저장된 설정을 지우지 않는다. 재로그인 후 입구에서 이어갈 수 있다. 입력 중 오류는 화면 안에 남기고 재시도를 제공한다. 네트워크 실패는 저장 실패 확정이 아니라 결과 미확인으로 안내하며 동일 요청을 안전하게 반복할 수 있다.

## 의도적으로 준비되지 않은 운영 입력

현재 저장소에는 승인된 실제 법률 본문·지원 주체·금칙어 목록이 없다. 따라서 코드/마이그레이션만 적용해도 이름 및 동의 단계는 준비 중 상태로 닫힌다. [DB 경계](../database/profile-onboarding.md)에 정의한 비공개 운영 정책과 불변 공개 문서의 **별도 승인·등록**이 필요하다. 이 기능은 그 승인이나 활성화를 수행하지 않는다. 이 프로필 저장 기능 자체에는 service-role key가 필요하지 않다. 별도의 서버 전용 맛보기 RPC만 [가수 탐색 설정](artist-discovery.md)에 설명된 서버 키를 사용한다.

CI 허구 문서를 실제 정책으로 복사하지 않는다. 정책을 변경할 때는 새 UUID의 새 본문을 승인/공개하고 현재 버전 참조를 바꾸어야 한다. 승인된 버전은 수정·삭제할 수 없다. 운영 설정/정책 갱신은 별도 승인된 운영자 절차이며 일반 사용자/관리자 HTTP 또는 service-role API 쓰기로 열리지 않는다.

## 검증

- Vitest: 서비스 입력/전이, API Origin·본문 한도·쿠키, DB adapter, RSC 권한·첫 렌더 크기, UI 입력 보존·기본 해제·버전 교체·중복 클릭·늦은 응답 처리.
- 기존 키 없는 Playwright 회귀는 그대로 유지한다.
- `auth-browser` CI는 실제 로컬 Supabase Auth의 폐기용 계정 및 고정 loopback Docker만 쓴다. 허구 정책은 CI helper에서만 설정하고 각 테스트 후 활성 설정을 제거하며 DB 종료 시 본문도 폐기한다. 외부 공급자·실제 사용자·이메일 전달·분석 전송은 사용하지 않는다.
- 글자 3단계 × 360/414px에서 글자/이름/동의 화면 18장, 실제 RPC 악성 입력, 반복 제출, 새로고침·Back/Forward·취소/재로그인, 준비되지 않은 정책, 버전 교체, 선택 분석 동의를 검사한다.
- 로컬 브라우저/DB 실행 제한은 회피하지 않는다. 실제 실행 통과 여부와 화면 검수 결과는 해당 커밋 CI 증거 및 작업 로그에서 확인한다.
