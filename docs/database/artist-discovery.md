# 가수 탐색·맛보기·관심 선택 DB 계약

## 범위

가수 선택은 **한 명의 관심 가수 선호**다. `private.artist_interests`에 현재 배우(actor)의 선택만 저장하며 구독, 결제, 유료 접근권, 읽음 증거를 만들지 않는다. 같은 가수를 다시 선택하면 최초 선택 시각을 유지하고, 다른 가수를 명시적으로 선택하면 교체한다. 건너뛰기 동작은 승인된 근거가 없어 제공하지 않는다.

선택 완료는 설치 안내 단계로 이동할 준비 상태일 뿐이다. `profiles.onboarding_completed_at`은 변경하지 않고, 이미 전체 가입이 완료된 사용자는 온보딩 선택 RPC로 선호를 변경할 수 없다. 별도의 일반 선호 편집은 이 기능 범위가 아니다. 전체 가입 완료 후에도 본인 관심 조회와 허용된 맛보기 조회는 현재 정책 조건을 다시 만족해야 한다.

## 호출 권한과 안전한 데이터

| RPC                                           | 호출 권한                          | 결과                                                                                           |
| --------------------------------------------- | ---------------------------------- | ---------------------------------------------------------------------------------------------- |
| `discovery_get_interest()`                    | `authenticated`, 실제 `auth.uid()` | `selected_slug`, `selected_name`, `selected_at` 한 행. 선택 없음/현재 비활성 가수는 모두 null. |
| `discovery_select_artist(p_artist_slug)`      | `authenticated`, 실제 `auth.uid()` | 현재 active 가수 한 명의 선호 저장. 사용자·시각·내부 가수 ID는 입력받지 않음.                  |
| `discovery_preview(p_actor_id,p_artist_slug)` | `service_role`만                   | 가수 공개 문구, 검증된 `call_name`, `messages` JSON 배열. 승인된 맛보기 없음은 빈 배열.        |

`discovery_preview`의 `p_actor_id`는 서버가 검증한 세션에서만 가져와야 한다. HTTP 요청이 제공하는 사용자 ID로 대체하면 안 된다. RPC는 실제 DB 역할·제한·현재 정책을 재확인한다. 원문 `body_template`은 서비스 내부의 공통 이름 치환 함수 입력이며 **그대로 클라이언트에 전달하지 않는다**. 일반 인증 사용자는 해당 RPC를 실행하거나 원본 메시지/미디어 테이블을 읽어 템플릿을 우회 취득할 수 없다.

미디어 배열은 논리 ID·종류·가로세로·재생 시간만 포함한다. Storage 경로·버킷·오브젝트 ID·원시 URL·작성자·회원/구독 ID·계약 정보는 반환하지 않는다. 이 기능은 업로드·서명 URL·파일 열람을 구현하지 않으므로 화면은 미디어 종류별 **사용 불가 안내**만 표시한다. 실제 사진/음성/영상 미리보기가 완성되었다고 주장하지 않는다.

공개 가수 목록은 기존 active 전용 `artist_catalog`에서 앱이 `slug,name,intro`만 명시적으로 선택한다. 기존 뷰의 원시 이미지 경로를 사용자 화면/DTO에 전달하거나 미검증 네트워크 이미지를 로드하지 않는다. 카탈로그 공개 여부와 개인화 맛보기 접근권은 별개다.

## 현재 준비 상태 재검증

관심 조회·선택·맛보기 모두 다음을 검사한다.

1. 실제 fan 역할, 현재 유효한 이용 제한 없음.
2. 글자 크기 선택·부를 이름·14세 이상 자가 확인·프로필 단계 완료 증거.
3. 현재 승인된 이름 정책으로 저장된 이름을 재검증. 정책 누락·미승인은 준비 안 됨, 금칙/길이 변경 위반은 프로필 재확인 필요.
4. 현재 승인되고 공개된 필수 이용약관/개인정보 문서와 **정확히 같은 버전**의 본인 수락 증거.
5. 선택/맛보기의 대상 가수는 현재 active. 숨김·중지·은퇴·없는 가수는 동일한 not-found 결과.
6. 맛보기는 현재 메시지 정책의 상한 안에서 `sent`·실제 발송 시각 도래·현재 맛보기 지정 메시지만. 구독 이력이나 관심 선택은 이 조건을 완화하지 않음.

정책·문구·가수·미디어는 이 마이그레이션에 운영 데이터로 시드하지 않는다. 테스트는 허구의 격리된 fixture만 쓴다. 설정 누락 시 임의 기본값으로 성공시키지 않는다. 선택한 가수가 비활성화되면 숨긴 가수의 이름/slug/시각을 반환하지 않고 설치 단계 준비 상태도 인정하지 않는다. 내부 선호 증거는 보존되며 가수/사용자 삭제 시 FK cascade로 정리된다.

## 경합과 검증

선택은 actor의 profile UPDATE 잠금으로 반복 요청을 직렬화하고, 공통 준비 검증은 profile → profile policy → artist 순으로 잠근다. 비활성화/제한/필수 정책 교체가 먼저 진행되면 대기한 요청이 최신 상태를 보고 실패한다. 맛보기는 artist SHARE 잠금과 현재 메시지 정책 잠금으로 가수 상태/기존 발송 취소 경로와 직렬화한다.

- `artist_discovery.test.sql`: 역할/grant/직접 접근, 현재 이름·법적 정책, 미완료·제한, 독립 사용자, 재선택·반복, 비활성 가수, 빈 맛보기·발송/취소/상한, 안전한 DTO, 구독·읽음·전체 완료 비변경을 실제 SQL로 검사한다.
- `test-discovery-concurrency.mjs`: 공식 로컬 Supabase의 독립 psql 세션에서 실제 잠금 대기를 확인한 뒤, 가수 중지 vs 선택, 가수 중지 vs 빈 맛보기, 제한 vs 선택, 정책 교체 vs 선택, 동일 선택 반복의 다섯 경합을 검사한다. 새로 reset한 격리 로컬 DB만 허용하고 종료 시 허구 fixture를 reset으로 제거한다.
- CI는 기존 DB/경합 회귀와 함께 이 테스트를 실행하고 실제 Supabase에서 타입을 생성한다. `src/types/database.ts`는 직접 작성하지 않는다.
- PGlite 보조 검사는 synthetic Auth/Storage schema의 SQL 논리 점검일 뿐 공식 Supabase PG17·PostgREST/JWT·실제 파일·독립 세션 경합의 증거가 아니다.
