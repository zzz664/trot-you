# 설치 안내와 전체 온보딩 완료

## 완료의 의미

현재 프로필(글자 선택·이름 정책·나이 자기 확인·최신 필수 정책 수락), active 관심 가수, 설치 안내 확인이 모두 있어야 전체 온보딩 완료 시각을 기록한다. 관심은 구독/결제/유료 접근권이 아니며, 설치 안내 확인은 실제 설치·알림 권한·Web Push 등록/전송 성공이 아니다.

브라우저마다 자동 설치 기능과 관측 가능성이 다르므로 안내 확인을 필수 기술 단계로 삼고 설치 자체는 강제하지 않는다. 지원 브라우저에서도 사용자는 설치를 건너뛸 수 있다. 설치했다고 명시하는 경우도 **사용자의 자기 보고**일 뿐 검증된 설치 상태로 저장하지 않는다. 알림 권한은 선택이며 어떤 권한 응답도 완료의 조건이나 서버 증거가 아니다.

## 기록과 RPC

`private.onboarding_install_guidance`는 본인당 한 행이며 `choice`는 `acknowledged`, `skipped`, `installed_self_reported` 중 하나다. 모든 선택은 실제 안내 확인을 뜻하는 최초 `acknowledged_at`을 보존한다. 마지막 선택이 자기 보고인 경우에만 별도 `installation_self_reported_at`이 있다. 완료 전 선택 변경은 가능하며 자기 보고를 취소하면 그 시각을 지운다. raw table 접근은 anon/authenticated/service_role 모두 금지하고 RLS도 활성화한다.

| RPC                                        | 동작                                                                           |
| ------------------------------------------ | ------------------------------------------------------------------------------ |
| `onboarding_get_install_state()`           | 검증된 현재 팬 본인의 선택·안내 확인·설치 자기 보고·전체 완료 시각만 반환한다. |
| `onboarding_acknowledge_install(p_choice)` | 현재 프로필과 active 관심을 다시 확인한 뒤 명시적 선택을 기록한다.             |
| `onboarding_complete()`                    | 현재 필수 조건을 다시 잠금 검증하고 전체 완료 시각을 반환한다.                 |

RPC는 사용자 ID·role·시각·알림 권한을 인자로 받지 않는다. `auth.uid()`에만 묶이고 profile → 현재 정책/정확한 수락 증거 → 관심 → active 가수 → 안내 기록 순서로 잠근다. 이름 정책·필수 정책 교체, 제한, 관심 철회, 가수 비활성화가 먼저 커밋되면 완료는 실패한다. 동시 완료/응답 유실 후 재시도는 최초 시각을 그대로 반환한다. 완료된 요청도 현재 필수 조건을 다시 검증하며, 과거 완료 시각은 실패 때문에 지우거나 새로 쓰지 않는다.

완료 후 같은 안내 선택의 재전송은 응답 유실 복구를 위해 허용하지만 다른 선택으로 수정하지는 못한다. 기존 프로필/관심 온보딩 쓰기 RPC 역시 완료 후에는 재사용할 수 없다.

기존 service-role profile 쓰기 권한으로 완료를 위조하지 못하도록 SECURITY INVOKER trigger가 응용 역할의 `onboarding_completed_at` 직접 INSERT/변경/초기화를 거절한다. 실제 SECURITY DEFINER 완료 RPC의 소유자 쓰기만 검증 후 통과하며, 기존 역사적 행은 마이그레이션이 재작성하지 않는다. 격리 CI fixture의 과거 상태 재현은 고정 local Docker의 owner SQL로만 수행하고 실제 서비스 역할 테스트는 거절을 검증한다.

## 범위와 검증

설치 확인 저장/완료는 정책이나 공급자 설정을 활성화하지 않고, 유료 구독·결제·푸시 구독·알림 전송·분석 이벤트를 생성하지 않는다. `signup_complete` 분석 수집은 향후 명시적 분석 동의/수집 경계에서 처리하며 선택 분석 동의 때문에 가입 완료가 실패하지 않는다. 배포와 실제 기기 설치/알림 전달은 별도 검증이다.

새 pgTAP 78개가 실제 Supabase용 fixture에서 역할/ACL·metadata 위조·선행 단계·현재 정책·현재 이름·가수 상태·명시적 선택·재시도·직접 쓰기 거절·연쇄 삭제를 확인한다. 독립 PostgreSQL 세션 경합 10개는 실제 잠금 대기를 `pg_blocking_pids`로 관측하며 policy/name/interest/consent/guidance/restriction 변경과 중복 완료를 검사한다. 기존 전체 회귀를 보존하고 DB 타입은 실제 Supabase 생성 artifact만 반영한다.
