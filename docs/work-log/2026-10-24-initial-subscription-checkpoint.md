# 첫 구독 등록·최초 청구 — 데이터베이스 검증 체크포인트

## 범위

`develop`의 `74f564e`에서 `feature/billing-initial-subscription` 한 기능 브랜치로 진행한다. 이 체크포인트는 실제 Supabase의 스키마 타입을 생성하기 위한 마이그레이션과 SQL 회귀 테스트만 포함한다. 아직 앱 완성이나 결제 운영 완료를 의미하지 않는다.

- 기존 체크아웃·구독·불변 원장·알림 아웃박스에 연결된 서버 전용 등록 상태, 암호문 보관 및 검증 결과 RPC.
- 계정·로그인 세션·nonce·약관·금액·가수·공급자·환경을 바인딩하고, 한 번의 영속적 dispatch claim만 허용한다.
- 승인 불명 상태는 재청구하지 않으며, Kakao 승인 응답 유실로 SID를 복원할 수 없는 경우 수동 확인 상태를 유지한다.
- 만료된 미청구 idle 등록만 현재 소유자의 명시적 새 준비 요청에서 정리한다. 불명·처리 중인 결제는 해제하지 않는다.
- 성공 후 재구독 시 가수별 최초 가격을 재사용하지 않는 회귀 검증을 포함한다.

## 검증 및 한계

- 별도 PG18/PGlite 보조 환경에서 전체 14개 마이그레이션 적용 및 SQL **2,271개 검증을 두 번 통과**했다(신규 144개 포함).
- 이는 실제 Supabase PG17, JWT/PostgREST, 독립 세션 동시성 또는 브라우저 검증을 대체하지 않는다.
- 독립 보안 검토에서 마이그레이션 체크포인트의 차단 이슈는 없었다. 정책 잠금 대기 후 TTL 재검사, 만료된 idle 복구 권한, 성공 후 재구독 차단을 검토·수정했다.
- 실제 CI의 마이그레이션·pgTAP·동시성·공식 생성 타입·전체 회귀는 다음 단계이며, 생성 타입을 수작업으로 작성하지 않는다.
- 실제 공급자 API 호출, 계정·가맹점 등록, 실사용 키 생성·저장, 결제·환불, 운영 배포를 수행하지 않았다. SQL 테스트 값은 격리된 허구 자료다.

추가 체크포인트에서 RPC의 선택적 동의·기간·암호문 인수에 SQL 기본값을 명시하여 공식 생성 타입에서도 생략 가능한 인수로 나타나게 했다. 원장·암호문·유료 접근·아웃박스의 동시 rollback 및 같은 검증 결과 재확정 테스트를 추가했다.
