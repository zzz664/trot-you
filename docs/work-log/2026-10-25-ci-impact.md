# 2026-10-25 — Dependency-aware CI selection

## Scope and preservation

PR #35 was merged before starting this CI-only feature. Remote readback showed
only `main` and `develop`; develop was
`4b4a9f55de1fb5c61302dcf0fc28d42eae570f65`, tree
`977f101bf91c2e993a8d31bcb33a6ab715cc4d38`. The clean previous local checkpoint
`34d203a7bd3461d394b4a9e3985739840374d41a` had the same tree. Its complete Git
bundle was created and verified outside the repository, and its branch was
archived before fast-forwarding develop and creating the sole active
`feature/ci-impact` branch. Main remained unchanged.

Only CI workflow/scripts/tests and documentation change. There are no application,
SQL, provider, business-policy, permission, branch-protection, or deployment
changes. Remote publication and exact-commit CI/merge verification are separate
from this local checkpoint.

## Decisions

- Enable conservative browser dependency groups immediately, not permanent
  shadow mode. Unknown paths, shared infrastructure, all runtime configuration,
  SQL/DB/adapters/auth, and workflow changes select every feature browser.
- Keep the complete quality job and full database regression for code PRs.
  Explicit documentation-only PRs may skip the DB and feature browsers.
- Retain every original step of all 21 existing jobs byte-for-byte, including
  both pgTAP passes, 28 race scripts, four populated upgrades, schema generation,
  drift checks, fixtures, browser tests, artifacts, and cleanup.
- Select the entire PR using verified merge parents and a merge-base/head diff;
  use NUL-safe path parsing, both rename paths, deletion paths, read-only fork-safe
  execution, and full fallback on uncertain history.
- Add a stable always-running `ci-required` aggregate. Missing/malformed plans,
  failed/cancelled/missing selected jobs, and unjustified skips fail closed.
- Preserve full main/release/manual/merge-queue paths without duplicating every
  develop PR run with a post-merge develop push run.
- Leave DB sharding to a separate measured change. The race/upgrade scripts reset
  the entire local DB, so parallel processes on one instance are unsafe.

Independent review found two dependency/robustness issues before publication:
runtime config schemas feed the global server environment and other features, so
the whole `src/config/` layer now selects full; the plan cap was lowered to 32 KiB
to leave room for the aggregate's nested needs JSON in environment variables.

## Offline decision replay

Replayed 100 available historical commit-to-parent diffs: 77 selected full and 23
selected feature groups. These are **individual-change simulations**, not claims
that those historical feature PRs would have skipped checks. Examples:

| Historical change                                     | Feature browsers selected                |
| ----------------------------------------------------- | ---------------------------------------- |
| `34d203a`: schedule/notice screenshot synchronization | Auth, schedules, schedule notices (3/19) |
| `6718414`: admin settings history capture             | Auth, admin settings (2/19)              |
| `65d4a47`: admin subscriptions fixture ordering       | Auth, admin subscriptions (2/19)         |
| `66efa97`: billing-notice navigation capture          | Notification dependency family (5/19)    |
| `04f1cdb`: payment reconciliation browser boundary    | Payment dependency family (7/19)         |

Also replayed all 65 archived feature heads against their actual merge base with
develop: **all 65 correctly selected full**, because their cumulative feature
changes include migrations, globals, workflow changes, or other shared inputs.
The failed schedule-notice checkpoint `ac1cfcf`, its wrapper correction `19a164e`,
and final PR #35 head `34d203a` all select full against their PR base `3570903`.
The new migration's known cross-feature dispatch regression therefore remains
covered. Updating a small fixture at the end of a migration PR does not erase that
PR's earlier migration impact.

This is deliberately honest about scope: independent leaf fixes can avoid most
feature browsers; cross-cutting feature PRs remain full. No wall-clock or monetary
savings percentage is claimed without new-run timing evidence.
